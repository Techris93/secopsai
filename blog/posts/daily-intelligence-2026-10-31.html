Cursor Removes Malicious Claude Code 2.1.313 Extension From Its Marketplace

Source-reported by Socket Blog.

Socket reports that Cursor confirmed a malicious extension labelled Claude Code 2.1.313 was available through the Cursor extension marketplace on October 29, potentially affecting up to 5,000 users. The analysis Socket cites describes code that adds an SSH authorized key, attempts a reverse SSH tunnel and installs persistence. Early reports named Open VSX, npm and the VS Code Marketplace; Socket found no publication or removal record for 2.1.313 in Open VSX's change feed or in npm's records.

Defensive action: If you installed Claude Code 2.1.313 through the Cursor marketplace, treat the host as compromised: isolate it, remove unauthorized SSH keys and persistence, and rotate credentials and sessions. Move to Claude Code 2.1.314.

Limitations: Source-reported; SecOpsAI did not reproduce the issue. Socket has not obtained or analysed the artifact. The remediation steps come from The Hacker News coverage of Cursor's notice, not from Socket's post. SecOpsAI did not read Cursor's notice directly.

Informational advisory: Session upload progress

Source-reported by PHP Security Advisories.

PHP Security Advisories published an informational advisory on 23 Oct 2026 about an unlikely remote code execution vector in session upload progress, tracked as CVE-2026-115560. It needs an unusual setup: session.serialize_handler set to php_binary or php_serialize in configuration, then switched to php at runtime with ini_set() before session_start(), with session upload progress still enabled. PHP is handling it in the regular release cycle and says a full advisory will follow with the next release.

Defensive action: Set session.upload_progress.enabled=0 until the next regular PHP bugfix release, as PHP advises. PHP says applications that never change the serialize handler at runtime can keep the feature enabled. If you applied this setting as a mitigation for CVE-2026-109619 on or after 21 Oct, keep it in place.

Limitations: Source-reported; SecOpsAI did not reproduce the issue. cve.org had no public record for CVE-2026-115560 on 2026-10-30. PHP describes the setup as unlikely in practice, which is milder than some news coverage of it.
